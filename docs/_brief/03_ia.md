# Information Architecture & Wireframe — termpdf-rs marketing site

> Contract for the implementer. Two engineers reading this should ship
> the same site. Copy lives in 02; visual design in 04.

## 1. Sitemap

v1: single-page site + one aux page. Anchors on `/` replace sub-pages
where the README crowd expects to scroll.

| URL          | Title                                       | Purpose |
| ------------ | ------------------------------------------- | ------- |
| `/`          | termpdf-rs — power-efficient terminal PDF reader | Landing page; pitches, proves, converts to GitHub or install. |
| `/keys/`     | Keys cheatsheet — termpdf-rs                | Standalone printable keymap, linked from footer + `?` overlay docs. |
| `/#install`  | (anchor on `/`)                             | Tabbed install instructions; deep-linkable from HN/Reddit threads. |
| `/#faq`      | (anchor on `/`)                             | Deep-link target for "but does it…" objections. |

Defer to v2: `/changelog/` (auto from `git tag`), `/benchmarks/`
(once we have multi-machine numbers).

## 2. Homepage section order

A 2am dev on a phone needs: what (1s), proof (5s), how (10s). Order
optimises that path.

1. **Sticky top nav** — nav bar. Orient + escape hatch. 1-row flex:
   wordmark left; Features / Power / Install / Keys / GitHub icon
   right. Hamburger <600px.
2. **Hero** — hero. "Pixel-perfect PDFs in your terminal, without the
   heat." 1-col centred: H1, subheadline, one-line install snippet
   with copy button, primary CTA (Install) + secondary text link
   (View on GitHub). Asciinema/animated terminal capture or static PNG
   placeholder sits below CTA, full container width.
3. **"Why this exists"** — paragraph + 3 pain bullets. Browsers and
   halfblock TUIs both fail; here's the gap. 1-col, max 65ch.
4. **Top features** — 3-col bullet grid (icon + title + 1-line blurb).
   Six things you get on day one. 3-col desktop / 2-col tablet / 1-col
   mobile. Cells: kitty rendering, vim keys, indexed search, in-PDF
   highlights, color-aware dark mode, link-follow.
5. **Power-efficiency proof** — comparison table + paragraph. 5-9×
   lower CPU than a browser, measured. 1-col, table max 600px wide.
   Two stacked tables (idle, scroll) using README's exact numbers
   (3.2% vs 17.1% idle; 7.5% vs 66% scroll). Caption links to
   `scripts/bench-vs-browser.sh` so visitors can verify.
6. **Animated terminal demo** — screenshot/asciinema. "This is what
   reading looks like." 1-col, full container width, lazy-loaded,
   captioned with the keystrokes shown.
7. **Install** — tabbed code blocks (cargo / pre-built binary / from
   source). Copy-paste and you're done. 1-col with tab strip; each tab
   body is one fenced code block. ID `#install`.
8. **Five keys to get started** — small table, 5 rows mirroring
   README. Enough to read with.
9. **Keys cheatsheet (collapsible)** — `<details>` wrapping the full
   Navigate / Highlight / Search tables. Collapsed by default.
10. **FAQ** — accordion (`<details>` per Q). Kill top objections before
    the issue tracker does. 6 entries: Linux-only?, terminal
    compatibility?, password PDFs?, EPUB?, tmux?, two-column papers?
11. **Footer** — 3-col link group, stacked on mobile. Cols: Project
    (GitHub, Issues, Releases) / Docs (README, Keys, License) / Meta
    (Rust + ratatui credit, BSD-3 pdfium credit, year).

## 3. Conversion goals

In priority order:

1. **Star + visit GitHub repo.** CTA "View on GitHub" — top nav, hero
   (secondary link under Install), footer. Lightest commitment;
   stars/week is the metric we can measure.
2. **Install locally.** CTA "Install" / "Copy" — primary hero button
   scrolls to `#install`; install section has per-tab "Copy" buttons.
   Conversion = paste into terminal.
3. **Run the benchmark themselves.** CTA "Verify on your machine" —
   text link in the power-efficiency caption pointing at
   `scripts/bench-vs-browser.sh`. Lowest volume, highest trust; a
   visitor who ran it shares the numbers.

## 4. Mobile breakpoints (<600px)

1. **Nav collapses** to wordmark + hamburger; menu opens as a
   full-width sheet, GitHub icon stays outside the menu.
2. **Multi-col grids → single column.** Features 3-col → 1-col,
   footer 3-col → stacked. Tables get `overflow-x: auto` rather than
   reflowing — comparison numbers must stay aligned.
3. **Hero shrinks**: H1 drops one type-scale step, install snippet
   wraps with horizontal-scroll fallback, asciinema lazy-loads only
   after first scroll to keep first paint under 1s on 3G.

## 5. Accessibility / SEO non-negotiables

- **Semantic HTML5**: one `<h1>`; `<header>`, `<main>`, `<section>`,
  `<nav>`, `<footer>`; FAQ uses native `<details>/<summary>` so it
  works JS-off and is keyboard-navigable for free.
- **Alt text on every image**, asciinema poster frame included;
  decorative SVGs get `aria-hidden="true"`.
- **WCAG AA contrast** (4.5:1 body, 3:1 large) in both themes;
  respect `prefers-color-scheme` and `prefers-reduced-motion` (no
  autoplaying demo for the latter).
- **OpenGraph + Twitter card meta**: `og:title`, `og:description`,
  `og:image` (1200x630 PNG with the headline benchmark),
  `twitter:card=summary_large_image`, canonical `<link>` to the
  Pages URL.
- **JSON-LD `SoftwareApplication`** structured data (name,
  applicationCategory=DeveloperApplication, operatingSystem=Linux,
  offers.price=0, license=BSD-3-Clause); plus `sitemap.xml` and
  `robots.txt` at site root.
